Проверка криптографического конверта

Локально проверяет AES-256-GCM, формат конверта и привязку шифрования к UUID отправителя и получателя. Данные этой проверки не отправляются в Supabase.

1. Создать приглашение (браузер получателя)

Создаёт случайный 256-битный invitation ID. В базе хранится только SHA-256 хеш. Передай ID во второй браузер.

2. Отправить тестовое сообщение (браузер отправителя)

3. Результат

Получатель должен обработать полную строку прямо из Realtime INSERT-события, без дополнительного SELECT. Отправитель отдельно проверит, что не может прочитать адресованную получателю строку.
